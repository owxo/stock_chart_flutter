# 开发需求标准

## 项目目标

`stock_chart_flutter` 面向 Flutter 金融应用，提供可复用的股票图表组件。组件应适合移动端、桌面端和 Web，重点保证行情展示清晰、交互自然、性能稳定、接入成本低。

## 核心功能需求

- K 线图：支持 OHLC 蜡烛图、成交量字段、移动均线、缩放、平移、十字光标和选中回调。
- 折线图：支持分时或时间序列数据展示、缩放、平移、十字光标和选中回调。
- 腾讯行情风格示例页：支持分时、日 K、周 K、月 K、五日等视图；默认不展示任何股票行情，只有调用方显式传入 `symbol` 时才请求远程数据。
- 示例应用：应提供股票代码输入入口，并支持通过 URL 查询参数 `?symbol=sz001896` 设置初始代码，便于在默认空态下显式加载真实行情。
- 主题定制：通过 `StockChartTheme` 控制背景、网格、文字、涨跌色、十字光标、折线和均线颜色。
- 跨平台交互：移动端支持手势缩放、拖拽和长按；桌面与 Web 支持鼠标悬停、点击、拖拽和 `Ctrl/Cmd + wheel` 缩放。
- 平台声明：`pubspec.yaml` 必须显式声明支持 Android、iOS、Web、macOS、Windows 和 Linux。

## 非功能需求

- 公共 API 应保持稳定，破坏性变更必须记录在 CHANGELOG，并优先提供迁移说明。
- 空数据、单点数据、同价数据和网络失败都必须有可预期表现，不能抛出未处理异常。
- 图表绘制应限制在可见区域附近，避免全量大数据重绘造成明显卡顿。
- 网络请求失败时示例页应保留已有真实数据或显示可理解的错误状态，不得回退为本地模拟行情。
- 包发布前必须通过分析、测试和 dry-run 发布检查。

## 验收标准

- 新增或修改图表能力时，示例应用能直观看到结果。
- 触摸、鼠标和滚轮交互在目标平台上行为一致。
- 主题颜色改变后，核心图形、文字、网格和十字光标仍清晰可读。
- 对外暴露的模型和组件在 README 中有最小可运行示例。
- 完成任务后当天开发日志记录完整。
